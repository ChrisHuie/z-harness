**The pivot (LOCKED 2026-07-11; 3 primary-source research passes — scratchpad `order-of-record-research.md`):** the substrate's commit target is an **order management / order-of-record**, NOT an impression-time ad server. Split the order layer in TWO seats: **Seat 1 = the serving-order** (line items that deliver) — TAKEN, publisher ad server, de-facto GAM (~90–93%, DOJ liable Apr 2025); adapt to it, don't fight it. **Seat 2 = the neutral cross-org record of the AGREED DEAL + lifecycle + receipts, independent of any ad server/interchange** — EMPTY / unclaimed. Seat 2 is the wedge.

**Why Seat 2 is provably open:** AdCP mandates durable persistence but DISTRIBUTES it across each seller (no neutral central store) — and thereby validates our DBOS thesis + names the agreement a **"commitment that functions as a programmatic insertion order"** (= our Commitment machine). Scope3 Interchange reaches for the SETTLEMENT/bank seat (4–8% margin on flow) but PUSHES the real order into the publisher's ad server and holds only "a coarser, derived view." AAMP/OpenDirect standardize objects+sync, store nothing. The salesagent sets `media_buy_id = the GAM order id` — nobody mints a NEUTRAL order identity. AdExchanger: "Agentic Advertising Isn't Reducing Intermediaries. It's Just Rebuilding Them." = the gap, confirmed.

**The clock:** Google shipped only an insights co-pilot (Ask Ad Manager, Jun 2026) but ANNOUNCED (not shipped, "later 2026") a proprietary agent front-door to GAM's order layer (specialized deal agents + GAM MCP server + REST trafficking APIs); NOT in AdCP/AAMP. Once it ships, GAM becomes the default agent-facing order surface and Seat 2 starts closing. First-mover window ≈ now → end-2026.

**The dual GAM strategy (user framing, 2026-07-11):** build something NOW that **circumvents GAM for any publisher who wants to and can — the hook is FEE CONTROL (escape GAM's take)** — AND ship **the most capable GAM adapter** for the ~90% who need it (no forced migration). Both sit on the ONE neutral order-of-record. Net: the record makes GAM **optional** (route around it OR use the best adapter), but the RECORD is always neutral and ours. = "make GAM one adapter, never the backend," now with a real adoption hook.

**Build decision (LOCKED): small CORE, real on GAM from day one.** Small-vs-all-in is a false binary because **GAM sync is harvest, not build** (salesagent `_legacy/google_ad_manager.py` wrapped behind our BookingSink port). GAM-from-start is needed because ~90% ARE GAM: a record that only reaches a mock is a demo; one that holds the deal neutrally AND pushes to real GAM proves "we sit ABOVE GAM, not inside it" = the whole thesis in one artifact. **The one anti-capture rule: our commitment object OWNS its own durable identity; the GAM order id is a foreign key in the sync adapter, NEVER our primary key** (the exact line the salesagent crossed).

**Clean separation — GAM must be REMOVABLE, not just present (user directive 2026-07-11):** break the GAM path and the off-Google agentic path into SEPARATE paths behind the BookingSink port — **mock** (Google-free proof) / **GAM** (stay, best-in-class) / **non-GAM|direct** (circumvent). GAM code lives ONLY in its adapter; the core knows no GAM. Guard = **`test_gam_is_deletable`**: negotiate→order-of-record→deliver runs end-to-end with the GAM package un-importable (same doctrine as `test_adcp_is_deletable`) — so publishers who want off Google can, and we prove it. Separate paths NOW (one build, config picks the sink), separable as a standalone product/brand LATER with no rewrite (clean seam = agility). Open, non-blocking (light research when we get there): what off-Google delivery concretely is per publisher — a non-GAM ad server (Kevel/FreeWheel/SpringServe) vs direct/self-serve; R1's mock sink already proves the Google-free path.

**BookingSink = a Prebid.js-style adapter ecosystem, but we DON'T maintain third-party adapters (user correction 2026-07-11):** the delivery layer is a stable PORT with many possible adapters — but **we build/maintain ONLY the port + our own stuff + GAM (harvested) + mock**, plus a deliberate FEW more if we choose (e.g. a direct/non-ad-server reference sink for the fee-free path). Everyone else's adapters — **FreeWheel (CTV), Kevel, etc. — are community/vendor-written against the port, NOT ours to build or maintain** (exactly Prebid.js: the core team doesn't maintain bidders' adapters). The maintenance TRAP to avoid: taking on a fleet of third-party adapters and redoing everyone's half-built code — the salesagent's non-GAM adapters (Kevel/Triton/Broadstreet/Xandr, BOK-added) are early stubs, NOT reliable harvest assets; don't count them. FreeWheel is a first-class *use case* (CTV = FreeWheel's turf), but a community/vendor *adapter*, not our build. **The GAM-free split is already architectural:** in BOTH the AdCP and AAMP flows, everything up to+including the durable agreed-deal record (discover→negotiate→order-of-record→receipts) is GAM-free by construction — both are GAM-free at the SPEC level; only their reference impls demo GAM / "push to GAM." The only GAM-touching surface is ONE step: the final delivery sync, isolated behind BookingSink. **"How to not pay Google fees" = the non-ad-server delivery path**, honest scope: deal types that need NO impression-time decisioning (sponsorships/takeovers/fixed/simple-guaranteed) → book into the neutral record + deliver direct = Google never touches it, no fee; programmatic/complex still needs AN ad server (GAM/FreeWheel/Kevel — publisher's pick, not necessarily Google).

**v1 cut — IN:** neutral canonical order+line-item model; Commitment lifecycle machine (aligned to OpenDirect `Draft→Reserved→Booked→InFlight→Finished`, conformance-clean); durable commitment object (own identity, idempotent, receipts, DBOS-backed); ingress = the AdCP↔AAMP bridge; BookingSink port with TWO adapters (mock = deterministic inner-loop/durability testing; GAM = harvested "it's real" path); verify-at-order-of-record (read back, fail loud). **OUT (build out from there — seams make each cheap):** billing/settlement/invoicing = **REFUSED not deferred** (that's the bank seat; ours is a utility, **no media-flow toll** = notary-not-bank at the record layer); **CRM/Salesforce integration** (user flagged as a real future need — "another day"); forecasting/make-goods/heavy OMS surface; more sync adapters (FreeWheel/Kevel); more ingress protocols; console polish; multi-tenancy/scale.

**Re-sequence:** R0 (DBOS crash/resume spike — now MORE central, the record IS the durable store) → **R1 re-centered = the neutral order-of-record, fed by the bridge, real on mock + GAM.** Old "R1 = bridge commits into GAM" → "bridge commits into the neutral record, which syncs to GAM." Pulls order-of-record + GAM-sync forward from R6.

**SCOPE (user correction 2026-07-11):** the near-term deliverable is the **FULL sales-agent rebuild interoperating with BOTH AdCP and AAMP** — order-of-record + both protocol faces + negotiation machine + GAM (removable) + durable execution + decision layer — **NOT a thin demo**. R0 (durability spike) is the first slice of the real build, not a throwaway. The R0–R7 pieces are the parts of the ONE agent, sequenced as build-order, not a series of demos. Docs that say "two-week saga-commit demo" / "thin bridge" under-scope it — reframe to "the sales-agent rebuild." The user drives the timeline; never time-estimate ([[feedback-dont-reference-time]]).

**Why:** the neutral order-of-record is the empty middle seat both giants must interoperate with and neither can hold — Google owns the serving-order beneath it but can't be neutral (monopolist under DOJ remedy); Scope3 wants the settlement seat beside it but can't be neutral (single-camp toll). Regulatory tailwind: post-DOJ, neutral ad-server-independent order interop is the pro-competitive layer the market wants. The substrate thesis ([[project-substrate-ownership-strategy]]) made concrete + time-sensitive.

**How to apply:** build the small core + GAM-from-start now; hold the own-identity rule and the no-toll rule as hard invariants; keep it QUIET (mechanisms public on neutrality merits; no Scope3/Google language in shippable docs — [[project-scope3-interchange-posture]] handling rule). Sustainability model must NOT be a media-flow toll (stay notary-not-bank) — open, "another day."
