**What earns the word "confident"** = the domain-model **money-safety kernel** (`docs/design/domain-model.md` §4.6). Money moves only on **final + dual-verified + in-tolerance + credit-cleared + disclosed-fee + undisputed** facts, **exactly-once, receipted**, and **every violation FREEZES rather than proceeds** (that last clause is the whole difference between a toy and real money). Invariants **I1–I14** + triggers **T1–T13** (§4.6; I14/T13 = the buyer spend-authority over-commit guard, [[project-two-seat-model]]). The load-bearing results from the multi-agent design pass (2026-07-12, folded into `domain-model.md` §4.6/§4.10/§4.11/§11 + `settlement-mechanism.md`): **INV-8 — the core never self-advances a positive money-fact** (`paid/reconciled/settled` are ingress-only, gated on cross-boundary signed evidence) ⇒ the substrate is a **notary, not a bank** (INV-1..11, **no Balance type**, `payer/beneficiary≠SELF`, fees are disclosed `FeeLine`s settled on the parties' rails). Money is compensated **FORWARD** (clawback = a new Obligation, I9 — funds on a party's rail can't be un-moved), the shared log has **authorized authorship** (§4.10.3 — no money edge is `Sole(party)`; P9), and money moves only on **N≥2 distinct-source** corroborated facts (no N=1 fallback). **Settlement is its OWN axis** (`SettlementState`, D12; `COMPLETED`=delivery done, `SETTLED/CLOSED`=money done). A **state-model** property, not a settlement bolt-on.
