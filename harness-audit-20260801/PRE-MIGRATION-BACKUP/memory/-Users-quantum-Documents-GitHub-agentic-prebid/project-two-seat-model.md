The buyer agent is **not a second system** — the core is already **seat-symmetric**: one `Commitment`, one fenced log, one money-safety kernel, both seats fold the SAME order-of-record; `authored_by` already names `buyer|seller`; money rides **`payer_ref`/`beneficiary_ref` refs, never seat labels** (so "paid" = buyer-paid & seller-received, seat in the refs). Doc of record = **`docs/design/two-seat.md`** (buyer-seat pass, 2026-07-12, folded from 3 dives: sink · authority · symmetry). Half of the [[project-real-money-first]] north star is the buyer agent, so under-building it threatened the goal — this pass closed it.

The buyer seat adds exactly (nothing forks the engine):
- **`operator_side ∈ {buyer,seller}`** — a role→identity **filter** (which seat am I?) from the authenticated principal, NEVER a request field; pinned across DBOS resume; replay-derived from `authored_by`. **Narrows, never widens** the `AuthPolicy`. Selects role-slot + wired sink + mandate. (Resolves IR-17.)
- **`Mandate.kind ∈ {spend,sell,governance}`** — buyer AP2/VC spend-authority (`ceiling`=max_spend) ⟂ seller `adagents.json` sell-authority (`ceiling`=None); both **witnessed authority facts** (AuthorityAssertion trust root + validity axis), a `declared`/`unverified` mandate **FREEZES** the money commit. (AP2 = [[project-transport-and-comms]].)
- **I14 + T13** (domain-model §4.6): **I14** = spend-authority conservation — an exposure-increasing edge admits only if `Σ portfolio_exposure ≤ verified ceiling`, else FREEZE. The **first CROSS-AGGREGATE invariant**; a pure fold over our own log (**we ARE the buyer's order-of-record → no `Balance`**, no external oracle on the consumption side — the deep buyer/seller asymmetry). **T13** = a witnessed ceiling cut/revoke freezes FUTURE binds, claws back NOTHING (buyer analog of T1). Both move no money.
- **`FundingHold`** — a witnessed per-deal FUNDS hold, the **true mirror of the seller's `ReservationHold`** (inventory); Tier-C-conditional on funding model (pre-pay/escrow/AP2-auth → armed; post-pay → T1/T4 gates instead).
- The **buyer sink** = DSP `BookingSink` + payer `PaymentAdapter` — the **same `SystemOfRecordSink` port**, buy-wired (`sink-contract.md` §5.6). **One seat = one deal** (per-`Package`, never ×`wseat` — buyer half of IR-23). Two buy-specific drift classes: **`deal-unbound`** (spending off-deal → FREEZE) + **`spend-mismatch`** (→ dispute, never auto-settle). Degenerate no-DSP direct buy → reading falls to a 3rd-party source or FREEZE.
- **Buyer delivery-reading source SETTLED** (IR-1): default = buyer's own DSP report **re-attested by the reference buyer agent** (independent at bid-win, incentive-correct: buyer wants it LOW, seller HIGH → opposite readings, gap FREEZES; also fills AAMP's buyer-report hole); **3rd-party verifier (DV/IAS/MOAT) = the N≥3 escalation** for high-value/disputed; pluggable `DeliveryReadingSource` port.

**The hold reconciliation (the crux — a 2×2, NOT two competing holds):** {authorization "may I?" · authored, OUR log} × {solvency "can I fund it?" · witnessed, EXTERNAL funding authority}, at {cross-deal · per-deal}. Cross-deal auth = **I14**; cross-deal solvency = **T1/T4** (existing); per-deal auth = **`exposure(k)`** (a fold TERM of I14, **NOT an object** — buyer-sink's "BudgetHold" was DROPPED: a stored earmark is a P0 second-source-of-truth); per-deal solvency = **`FundingHold`** (witnessed). They compose at the booking edge as authorization ∧ solvency. AP2 supplies BOTH (spend-mandate → I14; per-deal payment-auth → FundingHold) — which is why the dives collided.
