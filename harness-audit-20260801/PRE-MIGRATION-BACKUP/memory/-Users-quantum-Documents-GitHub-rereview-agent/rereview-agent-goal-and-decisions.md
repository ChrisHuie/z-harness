**Goal:** Universal, skills-based "rereview agent" for Claude Code + Codex CLI. Systematically inventories ALL prior PR review feedback (humans + AI bots), groups related items across reviewers/rounds, verifies in code what was addressed, detects refutations/clarification requests, posts a standardized GitHub report — so rereview rounds stop re-processing 7–8 rounds of raw comments and nothing is missed. Validated gap: no existing tool aggregates across reviewers, tracks refutation, or reports cross-round accounting; GitHub admits Copilot repeats dismissed comments; a 2025 study found 60–70% of LLM review comments go unresolved.

**Round-1 decisions (2026-07-24):** scope = track+group+verify+report ONLY (no fresh delta review, no auto-fix; other agents consume the ledger); state = hidden readable JSON ledger in sticky report comment + local cache; posting = one sticky report updated in place (no thread replies/resolving in v1); surfaces = local Claude Code + Codex CLI only.

**Round-2 decisions (2026-07-24) — state model locked:**
- **Three-axis model adopted** (flat enum empirically disproven on 389 real threads — every axis combination occurs):
  - Type (sets resolution verb): change-request | question (resolved by answer) | nit/optional | suggestion-block | praise/FYI; + normalized weight blocking|important|optional|info (mapped from P1/P2 ↔ Major/Minor/Trivial ↔ blocking/non-blocking/nit).
  - Axis A conversation: no-response | fix-claimed | partial-claimed | disputed (reasoned justification, rarely keyworded) | asked-reviewer | answered | reviewer-reasserted | acknowledged.
  - Axis B verification (diff vs HEAD, independent of words): untouched | changed-unverified | verified-addressed | verified-partial | verified-unaddressed (false claim — observed in wild) | regressed | superseded.
  - Axis C administrative: open | resolved-by-author | resolved-by-reviewer | resolved-by-bot | merged-open (18.5% of real threads end merged-open); isOutdated = weak hint only; resolver identity recorded (resolution habits are per-reviewer).
  - Derived report statuses: ✅ verified ✔️ answered ⚠️ claimed-unverified ❌ false-claim 🔶 partial ⚖️ awaiting-reviewer 🔁 re-raised 💤 unaddressed 🗑️ superseded 🙏 no-action ↩️ regressed. Derived ball-in-court: author|reviewer|nobody.
- **Report layout = ball-in-court**: sections 🔴 needs-reviewer-decision → 🟡 needs-author-action → ✅ settled (collapsed <details>); header counts + reconciled accounting line ("0 unaccounted"); permalinks for code evidence.
- **Verification = active groups + regression guard**: verify groups with new activity; re-verify previously-verified groups whose anchor files changed (fix-caused-regression observed empirically). Always diff HEAD, never cited SHAs (rebase-heavy repos rewrite them; 233 force-pushes on one Prebid PR).
- **Itemization = first-class + split**: review bodies and conversation comments enter the ledger with same state machine; multi-point comments split into separate items with stable sub-IDs; CI/bot noise filtered by classification. (Prebid.js culture: few inline threads, heavy conversation comments; its AI reviewer is chatgpt-codex-connector with P1/P2 badges.)

**Round-3 decisions (2026-07-24):**
- Issue scope: PRs only as targets in v1; linked issues read as context and as deferral evidence ("tracked in #N" verification); ledger schema kept issue-ready.
- Post flow (user's own words): "needs to be highly configurable so that we start as the approver but can get to full autonomy" → **autonomy ladder** as a first-class design principle: config levels like approve (preview+confirm every post, default) → auto-update (confirm first post per PR, then silent updates) → auto (full autonomy). The same ladder governs any future outward action (thread replies, resolving) in later versions.
- Label tone: diplomatic wording ("⚠️ Claimed — not found in current diff", not "❌ FALSE CLAIM").
- Brief mode: IN v1 — a mode emitting a compact (few-hundred-token) settled/open/disputed context block for other review agents to consume; this is the direct token-offload payoff.

**Round-4 decision (2026-07-24) — portability architecture:** centralized engine + native shells, NOT lowest-common-denominator. `core/` stays vendor-neutral (scripts, references, neutral SKILL.md body, ledger/report/brief formats); `adapters/claude` + `adapters/codex` exploit native features (argument-hint/allowed-tools/subagent parallelism vs openai.yaml/AGENTS.md fragment/curl transport); install.sh merges frontmatter overlay, body byte-identical across installs. Secondary harnesses (post-v1) via a defined Layer-2 adapter contract — grounded facts: Kimi Code CLI is near-free (agentskills-conformant, reads .claude/.agents dirs, `gh skill install --agent kimi-code-cli` target); ZCode (Zhipu/GLM harness) imports skills from Claude/Codex installs; dominant GLM/Kimi usage is Anthropic-compatible endpoints inside unmodified Claude Code → the Claude adapter serves those users. `.agents/skills/` = de facto neutral dir read by 8+ harnesses; `gh skill install` supports 43 agent targets. New engine rule: model-tier robustness (rubrics + hard gates; mid-tier models degrade conservative-and-flagged, never silently wrong). Interop planes: state (PR ledger shared cross-harness), context (brief), code (script CLI contracts).

**Primary target repo findings (prebid/salesagent, mined 2026-07-24; 374 threads / 10 PRs / ~1.0M chars; fixtures pr_salesagent_*.json):** NO third-party AI reviewer bots there — premise reframed. One dominant, likely agent-assisted reviewer account (plain User type; unresolved whether pure-agent — never name individuals in docs, see [[feedback-patterns-not-people]]) runs a MANUAL cross-round ledger in comment bodies: `↩ <raiser> <date> (<item-id>), still open|regressed: <finding>` (54×), "re-review item N", "S<n>" session tags — plus hand verification of claimed fixes ("marked done but the code doesn't show"). The tool automates exactly this. Key structural facts: threads are ≤2 turns ALWAYS (re-raises happen in NEW threads → provenance edges between threads, new Axis-A value `carried-over`); 76% of threads end unresolved; superseded (unresolved∧outdated∧no-reply) = dominant terminal 35%; reviewer resolves 0/354 (resolution = author discipline or bot auto-dismiss, bimodal per author). Parsing rule: non-empty review body = genuine reviewer pass, empty body = batch reply carrier (`reviews.totalCount` overcounts rounds 3–9×; rounds = distinct non-empty-review timestamps collapsed ≤3min). CodeQL bots: github-advanced-security (`## CodeQL / <Rule>`, dedupe by alert ID in trailing link, self-resolves, resolver login has [bot] but author login doesn't) + github-code-quality (HTML autofix block); pathologies: 11× duplicate alert pile, false-positive stalemate (author refutes, bot can't concede, dismissal needs maintainer → report routes as "needs maintainer action"). Severity vocab there: "Should fix"/"Nice to have". Dogfood target: salesagent#1544 (75 threads/14 rounds). Corpus total: 763 threads / 20 PRs.
