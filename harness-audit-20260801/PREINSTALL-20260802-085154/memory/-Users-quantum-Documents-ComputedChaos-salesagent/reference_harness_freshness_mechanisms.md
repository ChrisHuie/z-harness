The review harness commits the sin it exists to catch — validating against a stale PROXY instead of the derived source of truth. Two live instances found 2026-07-09 (triggered by red-teaming three externally-authored draft review agents against the current harness): `review-spec-conformance` + the `verify-spec` skill still pinned an old spec version long after #1399 bumped the repo (verify the current pin, never quote a literal — [[reference_adcp_spec_grounding]]); and the `# FIXME(#<gh-issue>)` convention (CLAUDE.md) had rotted to 88 beads-style `# FIXME(salesagent-*)` comment markers vs 40 compliant, with ZERO enforcement. This is [[feedback_escalate_recurring_lessons_to_guards]] applied to the harness itself — the design lives in `.claude/rules/private/harness-upgrade-spec.md` (miss-modes #5 stale-citation, #9 harness-self-staleness).

Mechanisms built (verify they still exist before relying — [[feedback_trace_flows_not_claims]]):
- **Citation-freshness detector** (gitignored reviewer tooling): `.claude/rules/private/detectors/citation_freshness.py`. Derives the pin via `adcp.get_adcp_spec_version()`; flags spec/SDK version literals in `src/` AND the harness that drift from it. Grounded exceptions: `# spec-introduced:` (a feature's introduction tag, per [[reference_adcp_sdk_spec_mapping]] §6) and `# version-literal-ok` (intentional/forensic mention). `--selftest` proves the matcher (pos+neg). `review-spec-conformance` runs it in detection step 1. **Extended 2026-07-23** (default roots now include `tests/bdd/features`; matcher gained an optional `v` prefix so the git-tag / `@source … ref=vX.Y.Z` citation form is caught, with a capture group normalizing the `v` away so a correct `ref=v<pin>` is NOT a false positive): a human colleague caught a wrong-version `@source ref=v3.1.0-beta.3` in two `.feature` files (PR #1697 R2) that the detector missed on BOTH counts — the `v`-prefix defeated the `\b\d+` anchor, and `.feature` files weren't in the default scan. This is the recurring lesson — when a human catches something MECHANIZABLE that a detector missed, extend the detector, don't just note it ([[feedback_escalate_recurring_lessons_to_guards]]). Meta-pattern: human reviewers excel at convention/consistency drift (wrong version, tag-vs-id drift, naming-polarity outliers); the harness excels at exhaustive enumeration (reserved-range batteries, sibling sweeps). Mechanize the convention-drift classes the humans keep catching.
- **FIXME-format detector** (gitignored reviewer tooling, NOT a repo guard): `.claude/rules/private/detectors/fixme_format.py`. Lists `# FIXME(...)` comment markers whose arg isn't `#<digits>` (88 pre-existing beads-style across 17 files) so the review agent flags any a diff ADDS. Scope: comment markers via `tokenize` COMMENT tokens beginning with `FIXME(`; string/docstring FIXME refs (xfail reasons, ~40) out of scope. `--selftest` proves the matcher. NOTE: first mis-built as a repo guard under `tests/unit/`, then reverted — a personal harness must never gate other contributors' CI ([[feedback_personal_harness_gitignored_only]]).
- **Recovery-audit detector** (gitignored; harness-upgrade miss-mode #1 — the original trigger): `.claude/rules/private/detectors/recovery_audit.py`. Introspects every `AdCPError` subclass's `(wire_code, recovery)` (code via `ERROR_CODE_MAPPING`) and flags (a) INCOHERENCE — one wire code with ≥2 recovery classes, and (b) SPEC-DIVERGENCE vs a verbatim snapshot of the spec `CODE_RECOVERY` table (transport-errors.mdx §Recovery Behavior; self-checks the snapshot version against the SDK pin). Recovery is buyer-actionable but storyboard-UNGRADED, so nothing else catches drift. Found on 2026-07 main: incoherent `SERVICE_UNAVAILABLE`(terminal/transient) + `INVALID_REQUEST`(correctable/terminal); 6 divergences incl. base+`AdCPConfigurationError` `SERVICE_UNAVAILABLE`=terminal (spec transient), `AdCPNotFoundError` `INVALID_REQUEST`=terminal (spec correctable), `AdCPConflictError` `CONFLICT`=correctable (spec transient), `AdCPBudgetExhaustedError` `BUDGET_EXHAUSTED`=correctable (spec terminal), `AdCPAuthorizationError` `AUTH_REQUIRED`=terminal (spec correctable — see [[reference_adcp_sdk_spec_mapping]] §6). Worklist, not verdict: explicit recovery may intentionally differ; adjudicate each.
- **SDK-vs-spec drift detector** (gitignored; harness-upgrade miss-mode #2): `.claude/rules/private/detectors/sdk_spec_drift.py`. Diffs the SDK's `STANDARD_ERROR_CODES` (36, runtime) vs a version-pinned snapshot of the published spec error-code enum (`dist/schemas/<pin>/enums/error-code.json`, 80 codes; refresh cmd in the file docstring; self-checks vs the SDK pin). The SDK is a DERIVED authority that LAGS the spec — codes the spec defines but the SDK lacks get FORCED into a less-precise mapping (a build-time assert requires wire codes to be SDK-standard). Found 2026-07: `CONFIGURATION_ERROR`, `CREATIVE_NOT_FOUND`, `BILLING_NOT_SUPPORTED` forced off-spec (the ROOT cause of recovery_audit's #1/#2 wire incoherences); `NOT_SUPPORTED` is SDK-only (absent from spec enum). Fires "REMOVE the mapping" when the SDK catches up on a forced code — run it on every `adcp` bump. FORCED codes are an upstream-SDK gap, not a repo bug.
- **`bump_check.py`** (gitignored; the drill) — `uv run python .claude/rules/private/detectors/bump_check.py` runs all 4 detector self-tests + scans in one command. ACTIONABLE = a self-test failure (exit 2) or a stale-snapshot WARNING after the SDK pin moved (exit 1, each detector's docstring has its refresh command); the standing counts (recovery divergences, forced codes, FIXME markers) are CONTEXT to compare against baseline, not per-run alarms. Run on every `adcp` bump / error-code change. The two snapshots that go stale on a bump: recovery_audit's `CODE_RECOVERY` + sdk_spec_drift's error-code enum.

Durable rule: a harness artifact (agent / skill / charter / memory) must NEVER hardcode a spec version — derive it. Stating a version literal in the harness is a bug the citation-freshness detector is meant to catch. Correction logged: the "3 `#gh-issue` placeholder markers" first suspected were actually prose *describing* the convention, not real markers — trace comment-vs-string/docstring before counting.
