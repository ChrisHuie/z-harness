All AdCP conformance **kernel/tooling is built standalone in repos we control** (home: `adcp-tooling`; monorepo to start, splittable later), **fully decoupled** from the salesagent repo AND from any `adcontextprotocol/*` repo.

External inputs ONLY: (a) the *published* signed spec tarball `/protocol/{ver}.tgz` (cosign-verified) and (b) a consumer's *published* `{code→recovery}` **dump-hook** JSON. The kernel never reads salesagent or adcp repo *source*; we publish our own packages (PyPI/npm/Go/Maven) and consumers depend on us.

**Why:** maximize standalone-ness + cross-language/cross-surface reuse; never couple the kernel to one consumer (the original sin was each SDK hand-curating a drifting table).

**How to apply:** never scaffold kernel code inside salesagent or fork an adcp repo; the drift-guard diffs a dump-hook artifact, not source. The design + build spec live at `adcp-tooling/.claude/notes/adcp-conformance-toolkit/{design.md, kernel-v0-spec.md, redteam-findings.md}`.
