Resolves the red-team's "attestation-grader = group-boycott / self-inversion" challenge (debate 2026-07-11). SUPERSEDES the "grader-of-last-resort, five locks" framing in [[project-agent-discovery-decapture]].

**The checkmark is FINE — it's the Prebid.js bid-adapter-compliance model, one layer up.** The group-boycott / essential-facility antitrust worry (Allied Tube, Hydrolevel) is about a CAPTURED standard-setter used to exclude; it DEFLATES for a neutral-open-permissionless model — which Prebid has run legitimately for 10+ years via bid-adapter compliance. What makes it legit (proven conditions, not a nervous hypothesis): neutral foundation + open published criteria + permissionless/Apache-2.0/fork-able (out-of-tree allowed; checkmark ≠ permission to exist) + transparent process + checkmark = quality signal, NOT a market-access gate. LESSON: ground agent-governance questions in how Prebid.js ALREADY operates, not abstract antitrust anxiety.

**Evolved to MULTI-CERTIFIER = "header bidding for compliance."** Not our-gate-vs-theirs: a neutral layer that DISPLAYS who-passes-whose-tests — Interchange / Prebid / IAB / Magnite as COLUMNS in a matrix — and the COUNTERPARTY picks the bar ("require IAB+Prebid", "Interchange is enough", "all three"). DE-CAPTURES Interchange BY INCLUSION: their test becomes one column, not the door (an app-store gate only has power if it's the ONLY gate). Pure de-capture-through-inclusion; the Prebid.js move (many sources shown neutrally, buyer/publisher chooses). We OWN: the portable attestation FORMAT + the neutral verify-and-DISPLAY. We DON'T own: the tests (each certifier runs their own) or the trust decision (each counterparty's policy). Mirror, not judge.

**Engine = automated PER-VERSION SANDBOX HARNESS.** A matrix is only meaningful if something actually RAN the agent and watched it pass. Sandbox testing bound to a version/hash = that engine, and it operationalizes freshness/revocation (new version → re-run → new attestation; the prior version's attestation expires by construction). MUST be an OPEN runnable HARNESS (agent dev runs it in CI per version; each certifier runs it; we author + give it away) — NOT a central sandbox-SERVICE we operate as the gate (tool-not-service; distributes cost). Honest limit: a sandbox verifies CONFORMANCE + probes KNOWN-bad behaviors deterministically, but CANNOT certify a non-deterministic LLM agent's FUTURE behavior → PAIRED with the order-of-record as the runtime WITNESS (sandbox = pre-deploy per-version; record = production audit). Neither alone.

**Why sandbox at all: agents are dangerous to just run** (untrusted autonomous code that acts). Isolation = HARDWARE-VIRTUALIZATION boundary — Firecracker microVMs (what AWS Lambda + Fargate are built on; purpose-built for untrusted multi-tenant code) or Kata Containers (VM-isolation with OCI/K8s ergonomics; can run on Firecracker) — NEVER bare Docker/runc (shared kernel = escapable). Defense-in-depth beyond the VM (stops damage a non-escaping agent still does): egress-control/no-net (SSRF/exfil), ephemeral one-shot microVMs, resource/time caps, NO secrets in the sandbox. SECOND boundary = the Gate/Commit mechanism: even a fully-compromised agent can only EMIT A PROPOSAL; the deterministic mechanism is the only thing that acts + it gates → blast radius bounded at TWO layers (can't escape the box + can't do what the mechanism won't authorize). Build-vs-buy RESOLVED (2026-07-11, research-grounded; premise validated by AWS "Lambda MicroVMs"-on-Firecracker, Jun-2026, shipped because containers can't safely hold untrusted code). Shape = a `SandboxProvider` PORT (create/exec/fs/set-network-policy/snapshot/destroy; secrets + orchestration state in the HARNESS, never the guest — the OpenAI Agents SDK ships this exact harness/compute split + "credentials are runtime config not prompt content," so we CONFORM to an emerging pattern, not invent; `cased/sandboxes` is a second prior-art impl). Open self-hostable REFERENCE isolation = **Kata Containers on Cloud Hypervisor** — the ONLY VM-grade option that's open + NEUTRALLY GOVERNED (OpenInfra Foundation, elected committee) + K8s-native + prod-proven; neutral governance is the decisive tie-breaker for a no-single-vendor substrate (every other open option — E2B-open, Microsandbox, firecracker-containerd — is forkable but single-vendor governed). Bare Firecracker = too much platform to build (networking/jailer/warm-pools/host-hardening all yours); Firecracker is an alt VMM under Kata but has hotplug/block-only limits → CH is the better default. Control-plane BLUEPRINT (lifecycle/egress-firewall allow-deny-domain-CIDR/snapshots/warm-pools) = **E2B-open** (`e2b-dev/infra`, Apache-2.0, purpose-built for untrusted-AI-code-in-Firecracker) — borrow patterns or offer as turnkey adapter (single-vendor governed → blueprint, not identity). Managed ADAPTERS behind the port: E2B cloud (strongest, Tier-1), Fly Machines (Tier-1, no official Python SDK), Modal (best Python/best-funded $4.65B BUT gVisor = Tier-2 → LABEL the tier), Northflank BYOC (self-host-without-owning-the-code middle). AVOID Daytona (went closed Jun-2026) + Blaxel (seed SaaS, riskiest). DAYTONA SIGNAL RESOLVED: open-sourcing the isolation PRIMITIVE is a STRENGTH (Kerckhoffs; Firecracker/KVM/Kata/CH/gVisor all open + battle-tested; AWS runs Lambda on open Firecracker) — only the DEPLOYMENT (secrets, network wiring, tenant topology) stays private; Daytona's close = commercial moat, not security truth. DISCIPLINE: inherit a battle-tested primitive (NEVER roll our own isolation), ship a SAFE-BY-DEFAULT reference, keep secrets/wiring out of the repo, be explicit that self-hosting shifts host/side-channel hardening to each adopter (Firecracker docs assign it there). Isolation tiers to sort any product: T1 hardware-virt (correct) / T2 gVisor (no HW-side-channel protection) / T3 Docker+V8-isolates (not for hostile code).

**THREE disciplines keep it neutral (break any one → we drift into being Interchange):** (1) attestations we MIRROR not own (signed, carried by the agent, self-published); (2) FACTS not endorsements (display "carries a valid signed Interchange attestation," never "this agent is good"); (3) REPRODUCIBLE + REMOVABLE (open harness + peer-to-peer verifiable without our display; index, not editorial list). Display Interchange's OWN signed attestation, never re-run their proprietary test (sidesteps storyboard-IP + stays verifiable). If Interchange won't make theirs portable → matrix shows "Interchange: not portable / unknown" = de-capturing pressure (exposes the walled garden).

**REVOCATION / freshness = the real new build** (the critic's missing-revocation gap): time-bound, revocable declarations/attestations; a changed/compromised agent's credential must be killable; stale attestations expire.

**ARTF — CORRECTED 2026-07-11 (was mischaracterized as "IAB agent trust framework").** ARTF = **"Agentic Real Time Framework"**: an RTB container-EXECUTION model where the HOST is the sole root of trust (provisions/schedules/monitors agent containers, mediates+audits ALL I/O, accepts/rejects mutations individually) — **NOT** an agent-trust/certification layer. AAMP's actual agent-trust layer is its **"Trust & Transparency" pillar = the IAB Agent Registry** (that is the certifier column, not ARTF). So ARTF is a **precedent/parallel for OUR sandbox+Gate isolation** (host-mediated-I/O + accept/reject + signed images ≈ Gate/Commit + microVM), and our multi-certifier model extends its **single→multi-trust-domain** at the certifier level. Conform (IAB = partner, not target); not a priority. Full fifth-authority resolution now lives in `docs/ARCHITECTURE.md` §9 + `docs/POSITION.md` §3.6.
