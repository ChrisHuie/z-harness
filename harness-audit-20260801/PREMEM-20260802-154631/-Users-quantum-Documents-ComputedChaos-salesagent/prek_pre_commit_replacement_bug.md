User's machine has `prek` (https://github.com/j178/prek) installed in the uv cache (`~/.cache/uv/archive-v0/.../bin/prek`). When `prek install` is run in any repo, it replaces `.git/hooks/pre-commit` with a script that invokes prek instead of standard pre-commit, AND sets `core.hooksPath` locally.

**Why:** Detected because prek installed `black-0.1.dev1+g1b2427a2b` (built from psf/black HEAD) when `.pre-commit-config.yaml` specified `rev: 24.10.0`. Standard pre-commit run via `uv run pre-commit run black ...` correctly installed and used black 24.10.0 against the same config. So the bug is in prek's rev resolution.

**How to apply:**
- If `make quality` (`ruff format --check`) and pre-commit's black are oscillating on a file's formatting, suspect prek + rev mismatch
- Check the hook: `head -5 .git/hooks/pre-commit` — if it says "File generated by prek", prek is in use
- Fix: `git config --unset-all core.hooksPath && uv run pre-commit install --overwrite` to restore standard pre-commit (this is a per-repo fix; affects only the current repo)
- Don't `prek clean` — it removes 1.3 GiB of cached envs but doesn't fix the rev resolution bug

**User context:** User did not knowingly install prek for the salesagent project. They were surprised it was involved. Treat its presence as user-environment background, not a project-level choice.
