Patterns extracted from PR reviews across PR #1276, #1306, #1311, #1312, #1274, #1262, #1263. Apply pre-emptively. Items marked ✓ have dedicated memory files.

**4+ times cited (universal):**

- **P1 Create/update validation symmetry** — every validator in `_create_*_impl` must also run in `_update_*_impl` with identical error wrapping. Detect: grep `validate_` calls in create.py vs update.py.
- **P2 No vacuous/tautological asserts** — `assert not isinstance(resp, Error) or all(...)` short-circuits when success. `"X" in str(dict)` is loose. Split compound `or` asserts; assert specific keys.
- **P3 Substrate ships with ≥1 production caller** ✓ — `feedback_substrate_prs_need_production_callers`. `grep "<name>(" src/` for every new helper.
- **P4 Generate from source of truth** ✓ — `feedback_single_source_of_truth_requires_deleting_duplicates`. Use `AdCPError.__subclasses__()`, `typing.get_args(Literal)`.
- **P5 Three-transport symmetry matrix** — MCP/A2A/REST identical caught types, log level, destinations (audit + activity_feed), wire shape.
- **P6 Hoist inline imports** — no body imports without circular-dep reason. Common offenders: `src.core.exceptions`, `resolve_identity_from_context`, repos, DB models.
- **P7 Narrow Any / list[Any]** — `list[Error]` not `list[Any]`. Drop `getattr` when type is known. Eliminate `type: ignore` by widening signature with `| None`.
- **P8 Raw dicts → typed Error/model** — `Error(code="X", message="Y")` not `{"code": "X", "message": "Y"}`. A2A skill handlers must `raise AdCPError` not return error dicts (✓ `feedback_a2a_skill_handlers_must_raise`).
- **P9 Happy-path/round-trip integration coverage** — PR's stated purpose has a test that fails on single-line revert. "byte-identical" claims need byte-level comparison test, not in-memory dict comparison.
- **P10 Deliberate-deviation needs inline comment naming spec text** — `# Deliberate deviation: <what + why + observability hook>`.
- **P11 Narrow `except Exception` + context-rich logging** — `exc_info=True`, all IDs (`media_buy_id`, `tenant_id`, `principal_id`), produce typed envelope not raw `{"error": str(e)}`.
- **P14 PR purpose has direct pin-test** — single-line revert of the decision breaks ≥1 test. Mutation-test mentally: "change line N → does any test go red?"
- **P23 Mock-only tests don't prove wiring** ✓ — `feedback_mock_only_tests_dont_prove_wiring`. Patching the dispatcher/transport verifies the mock, not the code. Every new error path needs ≥1 test per affected transport (REST TestClient, A2A `on_message_send`, MCP `env.call_via(Transport.MCP)`) exercising the actual wire. Gold standard: `tests/integration/test_a2a_error_responses.py:164`.
- **P24 Wire envelope, not reconstructed exceptions** ✓ — `wire_envelope_policy` (from PR #1359). NEW error tests MUST use `assert_envelope_shape(result.wire_error_envelope, code, recovery=..., message_substr=...)` from `tests/helpers/envelope_assertions.py`. Asserting on `isinstance(error, AdCP*Error)` or `error.error_code` or `exc.data["adcp_error"]["code"]` verifies the harness's lossy reconstruction layer, not the buyer contract. Reconstruction collapses `AdCPAuthenticationError`/`AdCPAuthorizationError` (both map to `AUTH_REQUIRED`) so it can't distinguish. Helper signature: `assert_envelope_shape(target, code, *, recovery=None, message_substr=None, check_backward_compat=False, check_mcp_tool_error=False)`. Per-transport call shape: MCP uses `check_mcp_tool_error=True`, A2A uses `check_backward_compat=True`, REST uses default flags.

**3 times cited:**

- **P12 Repository/UoW used; multi-entity writes commit consumer-visible state last** — buyer-facing state (MediaBuy status) before SyncJob "completed".
- **P13 Find existing helper before adding inline copy** — `resolve_enum_value()`, `PrincipalFactory.make_identity()`, `_future_dates()`. Pre-existing duplication shrinks, never grows.
- **P18 Named outcome types replace ambiguous tuples** — `(bool, str | None)` → typed `Outcome` enum/result. `(True, None)` meaning three things is the smell.
- **P21 Docstring claims match code; security-relevant kwargs keyword-only** — `status_code=500` default in error class invites 4xx-as-5xx misclassification. Read docstring → verify body matches.
- **P22 Compat paths get removability conditions + issue link** — `# Removable when <condition>` + FIXME ref. No "kept for compat" without a deletion criterion.

**2 times cited:**

- **P15 5+ mock decorator stacks → class-level fixture / harness** — new tests in legacy mock-heavy files still use harness/factories regardless of surrounding patterns.
- **P16 Tenant-scoped queries filter on `tenant_id`** — every `select(TenantScopedModel).filter_by(...)` includes `tenant_id=`. Cross-tenant reads are a security boundary.
- **P17 Adapter-boundary leak — service code string-matches adapter errors** — typed `AdapterTransientError`/`AdapterPermanentError` hierarchy; service catches typed, never inspects message strings like `"NO_FORECAST_YET"`.
- **P19 Repeated try/except skeletons → decorator or shared helper** — `with_error_logging` async/sync wrappers, `_handle_*_skill` exception ladders. Decorator-wrap or extract.
- **P20 Structural guards anchor on Path(__file__).resolve().parents[N]** ✓ — `feedback_structural_guards_pin_production_paths`.

**Round 7 additions (PR #1306, 2026-05-27):**

- **P25 Helpers introduced but bypassed at call sites** — When a PR introduces a canonical helper (`normalize_to_adcp_error`, `record_boundary_error`, `assert_envelope_shape`, factory methods), audit ALL call sites in the same PR for bypass. A consolidation that ships unused is debt, not progress. Detection: `grep <helper-name> src/` should match ≥1 call site for every consumer surface the helper was extracted to serve. The reinvention IS the defect — debt that ships during a substrate PR rarely pays itself back.
- **P26 Boundary symmetry: audit-log + activity-feed + log-level uniform across MCP/A2A/REST** — Extension of P5. All 3 boundaries must call the same observability sinks (`get_audit_logger().log_operation(success=False)` + `activity_feed.log_error()`) at the same severity. Divergence (MCP both, A2A audit-only, REST neither) = bug. Fix: extract `record_boundary_error(transport, tool_name, exc, identity)` that all 3 boundaries delegate to.
- **P27 Sanitization must preserve structured payload** — When enforcing a constraint (wire-code whitelist, schema narrowing) via rebuilding a typed object, the structured fields (`details`, `field`, `suggestion`, `context`) MUST survive. Replacing `AdCPError(msg, recovery=...)` with a constructor call drops everything else — webhook subscribers lose request-correlation context. Carry forward via dict-spread or explicit kwarg list.
- **P28 Test wire fields come from real wire, never synthesized via the same helper production calls** — Extension of P24. `result.wire_error_envelope` populated via `build_two_layer_error_envelope(exc)` in test code = lossy: the test exercises the same function production does, so a regression in either is invisible. Either capture from real wire bytes (HTTP body, ToolResult string, on_message_send DataPart artifact) OR rename to `synthesized_error_envelope` so test authors don't confuse the two. Update policy docs (`tests/CLAUDE.md`) so the next contributor doesn't lean on a field that doesn't deliver what it advertises.
- **P29 Test class docstrings match what the test actually verifies** — `TestA2ABoundaryAdCPErrorTranslation` that stops at `_handle_explicit_skill` and never drives `on_message_send → DataPart` is misleading. Rename to `TestA2AHandlerExplicitSkillReraises` OR extend to drive the real boundary. Naming claims wire coverage that isn't there.
- **P30 Tests pinning non-spec/dead wire shapes get deleted, not maintained** — `test_serialize_for_a2a_passes_dict_through` that legitimizes "A2A handlers may return error dicts without `adcp_error` key" is a defect when production no longer does this. Audit: if no production caller exists, delete the test. The test legitimizes a gap that no other test catches.
- **P31 Symmetric raises in same file converge to typed AdCPError** — Extension of P1. When line N raises typed `AdCPAuthRequiredError` for `identity is None` and line N+7 raises bare `ValueError` for `principal_id is None`, inconsistency within tight scope = bug. Detection: grep `raise ValueError` in `src/core/tools/*_impl.py` against sibling `raise AdCP*Error` lines in the same function.
- **P32 Eager-derived tables need late-binding completeness assertion** — `_ERROR_CODE_TO_STATUS = {cls.error_code: cls.status_code for cls in AdCPError.__subclasses__()}` evaluated at module import misses lazy-loaded subclasses. Add a structural-guard test that asserts every subclass appears at test-time. Pattern parallels `test_every_adcp_error_subclass_present_in_status_table`.
- **P33 Natural-language / non-skill handlers cannot bypass envelope contract** — NL entry points (`NL _create_media_buy`, push-notif handlers without `@_a2a_skill`) that emit `{"success": False, "message": ...}` dicts bypass `build_two_layer_error_envelope` and synthesize `MCP_ERROR` on the storyboard side. Either raise typed `AdCPError` (preferred) or delete the path. The two-layer-envelope structural guard doesn't fire on `return` — it only catches `raise`, which is exactly the wire-shape leak the substrate is supposed to close.

**Round (PR #1307 error-emission rework, 2026-06-01) additions — a review framed as "Everything below is required for the next review. Nothing is deferred and nothing is optional" = the WHOLE review is the blocker, not a one-item telegraph:**

- **P34 `error_code=` kwarg is a `synthesize()` bypass** — overriding the wire code via `AdCP*Error(..., error_code="X")` skips `synthesize()` (the only sanctioned override) and leaks codes absent from STANDARD_ERROR_CODES/ERROR_CODE_MAPPING to the wire, or advertises a status mismatching `status_code`. Fix: introduce a typed subclass; add a structural guard forbidding `error_code=` in `src/core/tools/` + `src/adapters/`, allowlisting only the canonical `synthesize()` callers. Drop `error_code=` that just repeats the class default.
- **P35 Error taxonomy belongs in a typed subclass, not `details["internal_code"]`** — `details` flows through `build_two_layer_error_envelope` to the wire, so an "internal" code label is buyer-visible, and a magic string isn't a taxonomy. Fix: one `AdCP*Error` subclass per legacy code appearing at >1 site (class attr carries the taxonomy; `ERROR_CODE_MAPPING` maps the wire code). Remove every `details={"internal_code": ...}`.
- **P36 Cross-transport error-normalization parity** (extends P5) — a broad `except Exception` decorator/wrapper that wraps as `AdCPError`(INTERNAL_ERROR→503) fires BEFORE the dispatcher's typed normalization (`ValueError`→VALIDATION_ERROR 400, `PermissionError`→AUTH_REQUIRED 403), so a decorated handler emits 503 where MCP/REST emit 400/403. Fix: narrow the decorator to let ValueError/PermissionError propagate to the dispatcher, or delete it.
- **P37 Uniform verb/prefix naming for an operation family** — three names for one op (`fail_workflow_step_for_exception` / `audit_step_failure_if_present` / `audit_step_failure`) means one `grep` doesn't find the primitive. Pick one prefix (`audit_workflow_step_failure*`) so the family greps together.
- **P38 Error-path tests pin the wire `error_code`, not just `isinstance`** (extends P24) — `pytest.raises(AdCPPackageNotFoundError)` with no code assert passes even if production swaps the raise to a PARENT class: `isinstance` stays true but the wire code flips (PACKAGE_NOT_FOUND→INVALID_REQUEST via ERROR_CODE_MAPPING). Add `as exc_info` + `assert exc_info.value.error_code == "<EXPECTED>"`. Adapter tests have NO `_impl` carve-out; even `_impl`-layer tests pin the code (the typed migration's whole point was locking wire codes).
- **P39 Structural-guard scan-set completeness** — code placed in a dir the guard doesn't scan is a silent escape hatch. `tests/helpers/adcp_factories.py` used raw `session.add()` and slipped past `test_architecture_repository_pattern.py` (scans `tests/integration*`/`admin`/`e2e` only). Fix: add the dir to the scan set (allowlist empty) AND fix the violation. **We did exactly this — `create_active_media_buy` in `tests/helpers/` to dodge the guard. Don't relocate code to evade a guard; widen the guard.**
- **P40 Don't assert on framework-internal error text** — `assert "greater than or equal to 0" in msg` is Pydantic-internal and breaks on a minor bump. Pin to `pytest.raises(ValidationError)` at the schema layer and assert the field path, not free-form text.
- **P41 Boundary/error-path code must never raise on edge cases** — `_serialize_context` raising `TypeError` on a malformed context shadows the original exception inside the boundary translator and fails open with no envelope. Translators/serializers/`to_dict` log + return a safe default; they never crash.
- **P42 Cross-adapter consistency: same semantics → same message AND same status** — adapters drift on "is missing" vs "requires" (dashboards substring-filter) and on 502 (`AdCPAdapterError`) vs 503 (`AdCPServiceUnavailableError`) for the same bulk-partial-failure event (clients status-filter). Standardize phrasing via a shared `_require_config` helper; pick one typed class/status per semantic event.

**Reinforced this round (already in catalog):** P2/P23 (tautological self-test never imports production — T2), P9 (dict-equality vs byte-level `json.dumps(sort_keys=True)` — T8), P4 (test helpers walking `__subclasses__()` → expose a production classmethod — T9), P13/P25 (open-coded dups of existing helpers: principal-not-found, budget validator, adapter config guard — A4/A5), P15 (243/137-mock behavioral files → harness; `side_effect=[mb,mb,mb]`/`repeat()` papers over call-count uncertainty + pins call order — T4), P21 (`_default_recovery="correctable"` contradicts "needs admin" docstring → terminal — A8), P30/P33 (dead flat-`error` fallback + A2A `InternalError` push-notif bypass — A2/A9/B6), P6 (lazy-import hoist incomplete; annotate each kept-lazy import with the exact reason inline — "defer until cold path" is NOT a reason — A6; ties [[reference_lazy_imports_load_bearing]]).

**Meta-lesson (#1307):** Many items were defects THIS rework *introduced* — `error_code=` bypasses, `details["internal_code"]`, the `tests/helpers/` guard-dodge, an f-string-logging regression of a previously-fixed nit, three commit messages drifting from the code. Pre-apply P34-P42 + the reinforced set BEFORE requesting review; after fixing a nit once, grep to confirm it didn't regress (`grep -nE 'logger\.(debug|info|warning|error)\(f"' src/`).

**Round 7 meta-observation (review of the #1359 sub-PR caught items):** the review flagged items 4 (synthesized `wire_error_envelope`), 6 (dead `if` in `_translate_to_tool_error`), and 11 (`fail_workflow_step_for_exception` drops fields) as originating from the reviewer's own PR #1359. Same bar applies. Lesson: substrate authorship doesn't exempt the work from the substrate-PR criteria.

**Hidden meta-pattern reviews surface:** "Same module, same PR, divergent implementations of the same operation" — very low tolerance for duplication introduced *within a single PR*. When a review cites "four of five review agents flagged this independently," the ask is non-negotiable.

**Telegraph for hard blocker vs nit:** reviews often end with a plain-text hierarchy. "After (X) lands, ready to merge" means X is the hard blocker; other items are nits that can ride.

**Substrate PRs are held higher bar.** "PR 1 of 3, the foundation everything else stacks on. It has to be airtight" — pre-apply ALL of P3, P4, P9, P11, P14, P25, P28, P33 on substrate PRs before requesting review.
