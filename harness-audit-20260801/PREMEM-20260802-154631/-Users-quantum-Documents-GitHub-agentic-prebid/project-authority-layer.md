The authority/trust/mandate/credential layer the money kernel (I1–I15) verifies AGAINST, consolidated 2026-07-13 from 5 grounding dives into its first home `docs/design/authority-layer.md` (was scattered across ~15 docs). Repo is source of truth; recall-pointer. Register: IR-51 (authored) + IR-52 (red-team).

**The unified model:** a **registry-over-origins federation** — ONE `TrustRoot` abstraction `{kind: origin|registry|governance, controller, keys, scope, revocation, economic}`; the neutrality doctrine = **own the keyring never the keys; own the verifier never the root; emit a `source×assurance` SET, never a scalar verdict** (collapsing to a score is the act that would make us the root → refuse). **Credential profile: VC-JOSE-COSE wholesale** — one JOSE/JWK family + one JCS canonicalization + one keyring, three carrier forms (RFC-9421 request-sig / detached object-sig over `Content-Digest(JCS(body))` / SD-JWT-VC); **JSON-LD/Data-Integrity rejected** (no money-grade Python DI lib → would shell to Rust/JS on the money path; RDF-canon `@context` poisoning; the frozen AdCP surface is pure JOSE). Assurance ladder (verified>attested>declared>unverified) = the money gate; **assurance = attribution, not truth**. Bind RFC-9421/JCS + the W3C VC 2.0 family (ratified 2025-05-15) + `adagents.json` (cosign-pinned; it DOES carry `signing_keys[]` — correcting an earlier "no key material" premise); config-pin-swap AP2/x402 (both changed governance hands last quarter); **author the objects AdCP lacks** (`Reading`/`SettlementEvidence`/`settlement_keys`/`RateAuthority`/`AuthorityAssertion`).

**THE red-team's core lesson (reusable; a 2-lens pass, both lenses converged):** the admissibility predicate must resolve the **SPECIFIC controller × scope × fact-type**, NOT just the root KIND. My first-pass "one pinned root per fact-type" was really "one KIND per fact-type," and the money gate collapsed to a **single spoofable bit** ("origin-rooted ⟹ verified ⟹ stand-alone"). Two CRITICALs: **RT1** — `source=governance` pins a kind not an issuer, so any trusted certifier VC issuer can forge advertiser A's `ceiling=$10M`, and nothing binds `op.principal==m.principal_ref` (an agent sets `k.mandate_ref=m_B`, I14 reads another advertiser's ceiling) → fix = a **kernel mandate-binding invariant** (`active_authority(m)=∅` unless principal-matches-or-verified-chain) + **split `source=governance` → mandate_issuer|accreditation|governance_review** + per-fact-type specific-controller pinning. **The multi-certifier matrix's own headline feature (trust many issuers) IS the attack surface.** **RT2** — attenuation-monotonicity is direction-blind ("no hop widens" as a naive subset test INVERTS for floor/brand-safety [narrower=higher] and exclusion sets [`[under-18]→[]` targets minors]) → a **typed per-field lattice** with direction encoded. **RT4 (root cause)** — no domain-separator inside the signed bytes on the shared keyring → a signature is re-aimable across consumers (freeze one cross-profile registry FIRST). Plus scope-not-gated (RT3), revocation defeated twice (RT5: signer-backdated `@created` + dropped 7-day rollback hold), `origin==self` self-issuance collapse (RT6), the delegation tier/SD-JWT/chain gaps (RT7 — money-mandates must be FULLY disclosed since SD-JWT "undisclosed=binding" is unenforceable), creative-approval no-root-row (RT8), refuse-to-collapse-cosmetic-at-the-gate (RT9). **Held:** F3/PC2 origin-identity pinning for `Reading`/`SettlementEvidence`; checker-never-server; `operator_side`. **NOT bankable enforcement until RT1–RT7 land; money-adjacent + delegated modes gate OFF meanwhile.**
