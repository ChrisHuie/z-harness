Design pass (2026-07-12, teammate charter) folding a new **§4.10 transition-as-trigger** engine + **authorization model** + **P8 bump / new P9** into `docs/design/domain-model.md`. The log (the order-of-record) is a **shared blackboard** both buyer and seller agents react to.

Core moves:
- **Reactor = transactional outbox**: a durably-committed transition atomically enqueues `reactions` (same Postgres txn, completing `durable-execution.md`'s outbox — not rebuilding it). At-least-once delivery, **idempotent by causing `fencing_sequence` + ordinal**. Reaction types: `append_transition`(cross-axis), `spawn_loop`, `notify/webhook`, `wake_agent`, `mint_obligation`, + `arm/disarm_timer`(liveness).
- **Authorized authorship (the headline, → new P9)**: every transition records `authored_by`; each edge declares a closed `AuthPolicy` (Sole/Counterparty/Dual/SystemOnly/SystemOnFact/External). No party unilaterally moves the record to its own benefit — money edges are Dual or SystemOnFact, never Sole(party). Seller can't stamp `COMPLETED→settle` (needs N≥2 co-signed); buyer can't stamp `REJECTED` (that's Sole(SELLER)). Assurance gates unilateral money-authorship; N≥2 corroboration substitutes for individual verification (ties I2/I3 + the co-signed oracle).
- **Transition KINDS**: fact (external claim, carries assurance, needs N≥2 before money) · decision (party-authored, mandate-scoped) · derivation (SYSTEM deterministic fold). Money-affecting = always derivation-on-corroborated-fact.
- **`caused_by: int`** = fseq of the cause; strictly-backward (`< fencing_sequence`) ⇒ causal DAG **acyclic by construction** (the fence gives acyclicity free). Plus `cause_kind: party|agent|cascade|timer` = the 4 trigger sources, all unified through ONE write path `propose_transition()` → same guards regardless of source.
- **Cascade safety** = acyclic-by-fence + closed-finite-catalog (static depth/fan-out bound) + one-choke-point (money-safety I1–I8 pointwise on every append) + idempotent effects. A cascade only *proposes*; the guard *disposes* → FREEZE (visible) if the money predicate fails; RAISE if illegal/unauthorized.
- **Validates the in-flight 15→13 cut**: RESERVED→timed hold-axis (`ReservationHold{held,expired}`), EXECUTING→exec loop + task-status; both are axes/loops, not lifecycle states — exactly what §4.10 formalizes.

Reconciles §4.6 (T1–T10 become reaction rules w/ author+kind columns; T10 & reservation-hold are liveness timers) and §4.9 loops (spawned by `spawn_loop`). **Interlock refinements (2026-07-12, from TemporalProjection / ExtendPlan / SafetyUnwind dives) — fold into §4.10:**
1. `caused_by` is `frozenset[CausalEdge{ref, role∈{trigger,precondition,supersedes,compensates}, commitment_ref?}]` — MULTI-cause (settle's causes = {finalized reading, N≥2 co-sign, credit-clear, fees-disclosed}). Roles first-class (power SafetyUnwind's `compensates` + delivery `supersedes`). The reaction row keeps a SINGLE `triggered_by` fseq for idempotency; the transition records the full set.
2. `StateTransition.payload: TransitionPayload|None` (typed: DeliveryReading|Receipt|FeeDisclosure|Correction|DecisionArgs|DerivationInputs) — facts live ON the log; DeliveryRecord/SettlementStatement are FOLDS/projections, not stored copies (P0 → flag §8 Entity-vs-projection to delivery-oracle/surface-map owners).
3. `actor_kind` is DERIVED from `(authored_by, cause_kind)`, never stored (P0). Keep both fields: `cause_kind` distinguishes timer-vs-cascade (both system-authored), `authored_by` distinguishes human(operator)-vs-party-agent. 4 minimal per-transition fields: authored_by, cause_kind, kind, caused_by.
4. AUTH-C2 (SafetyUnwind): `mint_obligation` + settlement-advance appends may appear ONLY in a money-safety derivation's reaction set, NEVER a lifecycle/creative/task trigger's → new guard `test_no_money_reaction_from_lifecycle_trigger`.
