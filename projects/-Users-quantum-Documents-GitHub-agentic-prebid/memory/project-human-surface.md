**LOCKED 2026-07-11** (user: "we aren't using flask… let's define a surface that is an api so you can bring your own frontend if you want but it is still testable"). The salesagent has a big welded UI (legacy Flask admin = 71 templates + 47 blueprints + landing; TS rewrite = a full React `packages/ui`); AAMP has NO human surface at all (verified: `/private/tmp/aamp-src` = ~13 pure-Python wire/object files, zero HTML/templates). So AdCP ships a monolith UI, AAMP ships none — our neutral surface is the bridge AND (for AAMP) the first operator surface that exists = "complete the protocol" at the UI layer.

**THE THESIS — the human surface is N-faces turned UPWARD.** Same neutral core: the wire has protocol faces pointing DOWN to counterparties (AdCP/AAMP adapters); the human surface is a face pointing UP to operators. **The rule that makes it a bridge instead of two UIs: the surface renders NEUTRAL domain objects, never the protocol payload — protocol is a labeled attribute + a raw drill-down (boundary-serialized once), never the STRUCTURE of a screen.** An AdCP deal and an AAMP deal are the SAME objects (Deal / Commitment / Hold / Booking / Receipt); a `[AdCP]`/`[AAMP]` badge + drill-down is the only difference. We never build an AdCP-console AND an AAMP-console — one operator surface over the core, each protocol a face below it. The neutral spine it renders is the core's own domain model ([[project-order-of-record-pivot]]): AdCP `media_buy` and AAMP `order` BOTH become the same `Commitment`. Bridges BOTH axes from one principle: AdCP⇄AAMP (neutral objects) AND buyer⇄seller (same shell, role-config).

**THE SURFACE IS AN API, NOT A UI.** A typed HTTP API over the neutral core is THE contract + the product. **Bring-your-own-frontend** — React, server-rendered, Slack, CLI, an existing dashboard, or an optional thin reference frontend we ship for out-of-box usability (config-first strong-defaults: configure-nothing → works). The frontend is pluggable, decoupled, NON-load-bearing. **BYOF SUBSUMES white-label** — bring-your-own IS the ultimate skin, so any earlier "theming seam" collapses into the API-first choice.

**STACK = NOT FLASK.** Single-async, pydantic-native, OpenAPI-generating (FastAPI/Starlette family; ASGI) — explicitly NOT Flask/WSGI. The salesagent's UI pain IS Flask: 47 admin blueprints bolted into the async server via `WSGIMiddleware`, 3 error idioms, sync-in-async blocking (see [[project-salesagent-lessons]] circumvented-problem #1). One async framework, typed boundaries, OpenAPI contract for free.

**TWO HALVES** (mirrors [[project-configuration-first]] "config editor + read-model view"): (A) READ/observability — `GET` over the neutral read-model: `deals`, `queue` (= pending-human workflow steps), `commitments` (+ booking/verification-at-the-ad-server state), `commitments/{id}/audit` (= the hash-chained RECEIPT chain — "why did the agent do this"), `workflows` (live monitoring), `counterparties` (+ the trust/certifier matrix — DISPLAY who-passes-whose-tests, operator picks, never we), `config` (effective/layered). (B) COMMAND/HITL loop — `POST` emitting DURABLE workflow signals: `accept · counter · reject · hold · release`, `PUT config`. Every command = typed request → durable workflow transition → typed response (errors by `recovery_class`, rendered as actions: correctable→fix-the-field, transient→retry-ETA, terminal→why+receipt).

**"STILL TESTABLE" = a FIRST-CLASS PROPERTY of API-over-UI, not a caveat — and the WHY-BETTER over the salesagent:** (1) typed contract → OpenAPI generated from pydantic → contract/round-trip test-vectors, same conformance-harness discipline as the protocol faces; `round-trip-or-raise` on the API boundary. (2) HEADLESS — surface is HTTP+JSON, tested with plain request/response asserts, NO browser (deletes the salesagent's welded-template + slow/flaky Playwright `tests/ui` category entirely). (3) COMMAND tests drive DURABLE workflow transitions (`counter→resume`, `approve→commit`, `reject→release-hold`), deterministic via `testing_hooks` (no wall-clock) — vs salesagent approvals in a raw `threading.Thread` + module-global dict that a RESTART DROPS and you can't durably test. Testable BECAUSE the queue IS the durable workflow. (4) READ tests assert projection incl. approval-queue = `SELECT … WHERE status='pending_human'`. (5) tenant-isolation tested AT the API — tenant from AUTHENTICATED identity, never a header (the exact salesagent bug; [[project-agent-runtime]] D1). (6) DECOUPLING that makes BYOF safe: a bring-your-own frontend tests itself against a MOCK of the contract (MSW-style) → the frontend NEVER gate-keeps the surface's testability. API verified headless; frontend verified separately.

**GUARD TESTS:** `test_human_surface_contract` (vectors round-trip), `test_counter_resumes_workflow` / `test_approve_commits` / `test_reject_releases_hold` (durable transitions), `test_queue_projects_pending_human`, `test_human_surface_tenant_isolation`.
